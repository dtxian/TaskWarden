# ADR-0002 · 桌面 UI 框架：Qt 6 + Rust 静态库（C ABI）

## 背景

目标是单进程、无 WebView2、低内存/低 CPU 的 Windows 桌面工具；安装包体积不是硬指标。
引擎（`core/` `runtime/` `infra/`，3,432 行、24 个测试、10 条语义）是项目最有价值、最难重写的部分。

评估过 ZSUI、Iced、egui、GPUI、Xilem、Slint、Qt，见 `../01`、`../05`。
最终环境验证：Windows 侧已有 MSVC 2022、CMake 4.4、Rust 1.98；Qt 6.9.3（MSVC 2022 64-bit）已安装并实测可编译运行。

## 决策

1. 桌面壳用 **Qt 6 Widgets（C++20）**。
2. 引擎 **原样保留 Rust**，编译为 `staticlib`，通过 **C ABI** 链进 Qt 应用。
3. 单进程；C++ 侧每 250ms 轮询快照 JSON，不做跨线程回调。
4. Qt 采用 **LGPLv3 动态链接**（`windeployqt` 随包部署 DLL），应用保持 MIT。
5. 不重写引擎、不引入 ZSUI/Iced/egui、不使用 vcpkg。

## 选项对比

| 选项 | UI 难度 | 内存 | 引擎 | 构建 | 结论 |
|---|---|---|---|---|---|
| Qt + Rust 静态库 | 低（Qt 成熟） | 中（实测空窗 38MB） | 复用 | MSVC+CMake+Qt+Cargo | **采用** |
| 全 C++ 重写 | 低 | 中 | 重写 3,432 行 | 同左 | 不采用（无资源收益，风险高） |
| ZSUI | 高（alpha + 缺口） | 低 | 复用 | Cargo | 不采用（成熟度/坑多） |
| Iced | 中 | 中高 | 复用 | Cargo | 不采用（托盘/无障碍缺口） |

## 后果

- 正面：界面能力成熟（托盘、日志框、单实例、表单、主题）、内存比 Tauri 低一个数量级、引擎零重写。
- 负面：C++ + Rust 两门语言；一层 C ABI；Qt DLL 随包（约 50MB 目录）；MSVC/CMake 工具链比 cargo 重。
- 需同步：README、`AGENTS.md`、`PI-work/06`、`THIRD_PARTY_NOTICES.md`。

## 验证

- Qt 空窗口实测：WorkingSet 38.1MB / Private 7.3MB / 1 进程。
- 迁移验收：12 任务 + 200 行日志下 WorkingSet ≤ 100MB、空闲 CPU ≤ 2%、进程数 1。
- Rust 24 个测试在 Windows 上全绿。

## 复议条件

- Qt 许可证/部署方式必须改为静态链接（需 GPLv3 或商业授权）；
- Qt 版内存超过 150MB 或 4Hz CPU 超过 5%；
- C ABI 出现无法隔离的崩溃/UB；
- Windows 侧工具链不可用。
