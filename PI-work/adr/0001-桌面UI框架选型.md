# ADR-0001 · 桌面 UI 框架：Tauri 2 + React → ZSUI（条件接受）

> **已被 `ADR-0002` 取代（2026-10-29）：最终选择 Qt 6 + Rust 静态库。** 本文保留为评估历史。

## 背景

当前桌面端为 Tauri 2 + React 18，核心引擎为纯 Rust（`std::thread + mpsc`）。
已知成本：双语言、IPC + DTO 双份语义、WebView2 进程树内存高、交叉编译产物需
`WebView2Loader.dll`。ZSUI 是原生 Rust UI 框架，模型与现有引擎线程契合，且实测
内存/启动量级更优；但处于 0.3.0-alpha.2，单人维护，stable 接口覆盖不到托盘/主题。

详见 `00-现状基线.md`、`01-zsui-评估.md`。

## 选项

| 选项 | 优点 | 缺点 | 风险 |
|---|---|---|---|
| A. 保持 Tauri，定点优化 | 零迁移风险；保留视觉与网页 demo | WebView2 重量、双语言、DTO 双份语义仍在 | 低 |
| B. 迁移 ZSUI | 单语言/单进程、内存降一个量级、真正单文件 | UI 重写 6–8 周；视觉降级；alpha 依赖 | 高 |
| C. 迁移 Iced / Slint / egui | 比 ZSUI 成熟 | 各有硬伤（许可证/内存/CJK/生态） | 中 |

## 决策

**条件接受 B**：

1. 先做 2 周 Spike，通过 `04-验证清单.md` §1 的 10 项门禁；
2. 同时把落地页拆成独立 `web/`（无论 Go/No-Go 都执行）；
3. 10/10 通过 → 按 `02-迁移方案.md` P2–P4 执行；任一失败 → 转 A；
4. 迁移期间 `src-tauri/` 保持可构建，不提前删除。

## 后果

- 正面：去掉 IPC/DTO/mock-live 双份语义；单文件 exe；内存与启动显著改善；CI 简化。
- 负面：UI 全部重写；视觉从「自定义 egui 风」降为「原生 + 主题 token + Canvas 点缀」；
  落地页不再与桌面端同源；需承担 0.x 升级适配。
- 同步修改：`README.md`、`src/data/content.ts`、`src/data/snippets.ts`、`AGENTS.md`、
  `.github/workflows/*`、`deploy/*`、新增 `THIRD_PARTY_NOTICES.md`。

## 验证

- Spike 结果表（`04` §1 末尾）10/10 绿；
- 全量验收（`04` §2）全部打勾；
- 性能目标：exe ≤ 8MiB、RSS ≤ 60MiB（12 任务）、4Hz CPU ≤ 2%。

## 复议条件

- ZSUI 连续 3 个月无提交或关键 issue 无响应；
- 升级到 0.4/0.5 时出现无法隔离的破坏性变更；
- Spike 任一硬门禁失败；
- 作者改变优先级（自定义视觉/网页演示 > 轻量）。
